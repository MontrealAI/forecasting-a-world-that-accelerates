# Prospective Validation Program

The ceiling edition distinguishes four claims:

1. **Mechanical correctness** — the code, schemas, tests, builds, and checksums operate as specified.
2. **Controlled identification** — known synthetic regimes reveal whether implementations recover or fail under specified mechanisms.
3. **Historical discrimination** — frozen public evidence can compare candidate models through rolling-origin pseudo-forecasts.
4. **Prospective calibration** — forecasts registered before outcomes are observed can be scored without hindsight.

Only the fourth level can establish real-world calibration over time.

## Minimum prospective program

Register at least twelve targets spanning technical capability, cost per verified outcome, autonomous task completion, organizational adoption, and realized operational output. Preserve exact evidence cutoffs. Score point forecasts, intervals, milestone probabilities, and decisions using log error, CRPS, weighted interval score, Brier score, calibration curves, and decision regret.

Report all registered cases, including failed and withdrawn forecasts. Do not optimize the protocol on the held-out prospective registry without declaring a new protocol version.

## Benchmark governance

- Freeze benchmark definitions and source snapshots.
- Record configuration, model, scaffold, attempts, tools, and evaluation code.
- Treat benchmark version changes as measurement-regime changes.
- Separate in-domain benchmark gains from fresh-task transfer.
- Maintain a public corrections log.
